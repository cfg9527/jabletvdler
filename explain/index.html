How this downloader is designed.

This page explains the two design artifacts in docs/design/: the architecture note (design.md) and the visual taste primer (taste.html). Together they describe a Textual TUI that downloads HLS video, then dresses the terminal in unapologetic pink.

What the design output is

The design output is not a Figma file. It is two complementary documents that encode product intent and visual identity, then point at the Python that already implements most of it.

design.md — the machine

Goals, non-goals, component tree, download pipeline, dependency choices, and risks. This is the “why Textual / httpx / threads / ffmpeg” document. Read it when you need to know how a pasted URL becomes an MP4.

taste.html — the costume

Palette, chrome, motion, screen mocks, and taste rules. This is the “why the window breathes and hover snaps to hotpink” document. Open it in a browser; the border should inhale. Source of truth for color is still jabletv/themes.py.

Pink is the brand. Periwinkle is the job. Hover is the blush. Taste primer thesis · PinkyTheme

Product intent

A terminal-based downloader for adult video sites that speak HLS (m3u8). The user pastes a URL, confirms they are 18+, and watches segment progress in a pink-framed window. Output is a clean MP4 plus a JSON sidecar in jable_db/.

1Paste URL
2Scrape metadata
3Fetch HLS segments
4Decrypt / concat
5ffmpeg → MP4

Goals (from design.md)

  • Download via URL input, not crawl/search
  • Textual TUI with live progress
  • Concurrent segment downloads
  • AES-128 encrypted HLS
  • MP4 via system ffmpeg

Declared non-goals (v1)

  • No web UI
  • No multi-site support in v1
  • No catalog crawler
  • No Docker packaging

MissAV is already in the code; see Drift.

Architecture, explained

One Textual App owns the chrome. Screens push and pop inside a single #window-wrapper. The download engine is ordinary Python threads talking back to the UI with call_from_thread. Nothing about the pipeline is async; the TUI is.

Data flow

The scraper does not download video. It only extracts a VideoInfo dataclass (code, title, actresses, tags, thumbnail, m3u8_url). The downloader then treats that playlist as the job. 

URL
 │
 ├─ jable.tv  → scraper.scrape()
 │                regex on <script> vars → VideoInfo
 │
 └─ missav.ws → missav_scraper.scrape_missav()
                  unpack eval’d JS → surrit.com playlist → VideoInfo

VideoInfo
 └─ downloader.download(video, progress_cb)
      ├─ resolve master m3u8 → variant playlist
      ├─ parse segments + AES key/IV
      ├─ ThreadPoolExecutor(8)
      │    ├─ GET each .ts
      │    ├─ AES-CBC decrypt if encrypted
      │    └─ cache under .parts/ for resume
      ├─ concat .ts
      └─ ffmpeg -movflags +faststart → downloaded/CODE - title.mp4
           └─ metadata_store.save_metadata() → jable_db/CODE.json

Why those libraries

ChoiceInstead ofReason
Textual CustomTkinter SSH-native, Rich markup, one CSS theme file. Fashion has to survive a monospace grid, so it is painted in large strokes (heavy border, figlet, full-width bar).
httpx requests HTTP/2 for CDN connection pools. Optional curl_cffi impersonation when Cloudflare 403s the default client.
ThreadPoolExecutor asyncio gather Segment I/O is bound on the network. Threads are simpler than mixing Textual’s event loop with hundreds of coroutines.
ffmpeg manual MP4 mux Correct container + faststart. Documented system binary, not a Python wheel.

The UI only owes the user three reports of work: a blushing progress bar, a speed sparkline, and a centered status line. httpx, AES, and ffmpeg stay invisible.

Visual taste, explained

The primer’s claim is that this is not “dark mode with a pink sticker.” The room is navy-black (#161a26). Identity is the window itself: a heavy pink frame that eases between #fe628e and #ff69b4 every three seconds. Work buttons start periwinkle. Pointer events snap to hotpink + white + bold — desire as a hover.

Chrome

Every screen lives in #window-wrapper at 100% fill with border: heavy $accent. Inner panels use stone (#5e5d5a) until focus, then they flush pink. The workbench is 80 characters, centered. Type hierarchy is color, not size: primary, secondary, muted. Metadata uses Rich markup — cyan codes, yellow names, italic tags.

Motion

Two motions only. Ambient: the outer border animates 3s toward hotpink and 3s back — implemented in JableDownloaderApp._breathe_border(). Pointer: hover does not fade; it snaps. The sparkline is the only extra animation, and it reports speed rather than decorating.

Taste rules (implementation constraints)

  1. Pink is identity, not a highlight. Remove it and the product must not look like “any TUI.” Frame, figlet, hover blush, and progress fill stay pink.
  2. Periwinkle does the work. Download / Open / Yes may start cool and blush on hover. Do not paint every button pink at rest.
  3. Navy is a room. Keep #161a26 / #191d28. Pure black or warm charcoal makes the rose cheap.
  4. Quiet structure, loud color. Centered stacks, muted borders, one theatrical object. No fake OS chrome.
  5. Hover snaps. Ambient breathes. Border: 3s ease, two pinks. Pointer: instant hotpink + bold + white.
  6. Ceremony at the edges. Age-gate the session. Bilingual gold/amber warnings. Leave room for a farewell — do not replace designed ritual with a toast.

Where design and code disagree

The documents are a snapshot of intent. The repo has already moved in a few places. Treat these as known gaps, not bugs in the primer.

Multi-site. design.md lists MissAV / SupJav as a v1 non-goal. The shipped TUI already accepts missav.ws / missav.com and routes through missav_scraper. The taste primer’s download mock is correct; the architecture note is stale on this point.

Completion ritual. Theme CSS already styles #complete-screen, confetti, checkmark, and #farewell-art. app.py currently logs “Complete!” and pushes the dashboard. The primer asks not to replace that theatre with a toast — implementing those screens is still open work, in the same voice.

Risks that still apply. jable.tv can change the m3u8 embedding pattern (regex scrape). CDNs can add Cloudflare (already mitigated with optional curl_cffi). ffmpeg must be installed on the machine. Python 3.9 limits annotation syntax.

How to use these files

  1. Open docs/design/taste.html to feel the product — border, palette, hover, screen mocks.
  2. Read docs/design/design.md for pipeline and dependency decisions.
  3. Use this page as the translation: what each document means, where it is implemented, and where it is not.
  4. When changing UI, obey the taste rules before adding a new color or a second animation.
